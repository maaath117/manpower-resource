## 三、访谈问答原文

### 顾明岚 · 业务负责人

**问（目标）**：这次最希望达成的业务目标是什么？

**答**：先把目标说清楚：这次不是追求把核对全部自动化，而是让入职服务单减少重复核对，同时必须保留人工确认和可追溯来源 。这两条是硬约束，任何试点方案都不能绕开。 我这边负责的是价值判断和试点范围决策，所以我会先问：你希望试点覆盖哪些区域、哪些材料类型？如果范围铺得太大，人工确认环节的压力会反向增加，价值就说不清。另外，减少重复核对具体指哪一段重复——是专员之间重复录入，还是跨区域交接时重复核验？这一点尚未核实，需要你澄清。 我的建议是先选一个区域、一类高频材料做小范围验证，把可追溯来源作为验收前提，但这只是待验证假设，要等一线和流程同事的口径对齐后再定。

**问（流程）**：请讲讲现在实际的处理流程。

**答**：实际链路我这边掌握的是：客户提交→区域核对→补件→服务确认 。我的判断是先把每个交接点看清楚，再谈要不要上自动化，直接加系统动作容易把责任边界搅乱。同时这次的目标是让入职服务单减少重复核对，但人工确认和可追溯来源必须保留 。所以我想先确认：你说的“实际流程”是指标准链路，还是某个区域已经跑偏的做法？另外各交接点目前谁签字、谁负责补件催办，我这边尚未核实，需要唐映秋那边给口径。试点范围我倾向先选一个交接最频繁的区域，但具体选哪个、验收看什么指标，得等流程和异常数据摆出来再定。

**问（验收）**：怎么验收成功？试点标准是什么？

**答**：验收我这边只认一个可量化的口径：抽查50单，至少45单一次给出完整缺件清单 。这条是硬指标，达不到就说明“减少重复核对”这个价值没兑现，试点不能往下一批推。 试点范围我倾向收窄：只覆盖一个批次的入职服务单，只做材料完整性提示，不自动办理入职，也不判断用工合法性 。这两条是边界，越过去就不是我能拍的范围，涉及合规要傅景那边先给意见。 需要你澄清两点：一是“一次给出完整缺件清单”由谁判定、按什么口径记录，这直接决定验收能不能复核；二是这个批次选哪个区域、多少单量，我还没看到依据，尚未核实。建议先定判定人和记录方式，再谈批次，这属于待验证假设。

**问（预算）**：试点预算是多少，成本怎样核算？

**答**：预算这块目前能明确的是：先限定为四周试点、两名业务骨干参与，每周投入不超过四小时，超出须重新评估 。这是执行条件，不是财务口径。 成本怎么核算，我这边尚未核实，不能给你一个核算方法。我的立场是：试点范围要压在这个投入边界内，否则我不签字。建议按人力投入工时为主来归集，但这是待验证假设，需要和财务确认口径后再定。 反过来我要问你：你说的成本，是只算我们业务侧的人力，还是要把跨区域协同、复核环节的投入也算进来？口径不同，试点范围会差很多。另外验收上你打算用什么指标证明减少重复核对，这个也得先讲清楚，否则四周结束我没法判断要不要扩。

**问（决策）**：谁参与决策，谁可以否决方案？

**答**：决策边界我先说清楚：试点范围由我定，但审核与质量负责人保留停止试点的权利，客户协同代表负责确认结果用途 。也就是说，我能决定“试多大、先试哪块”，但试点的合规与质量红线不在我手里，一旦傅景那边判定风险不可控，试点要停。 所以我想先跟你确认：你说的“否决方案”是指停掉整个试点，还是只否掉某个具体环节？这两者对我的范围决策影响完全不同。另外，试点范围我倾向先圈一个可验证、可回退的小切口，但具体圈哪块、验收口径怎么定，还需要你澄清目标后再谈，目前尚未核实。

**问（范围）**：首期优先做什么，试点覆盖哪里？

**答**：首期我倾向先把范围收窄：试点只覆盖一个批次的入职服务单，只做材料完整性提示，不自动办理入职，也不判断用工合法性 。这条边界是我能拍板的，再往外扩就涉及用工合规判断，不在我职责内，需要另行审批。 做法上，我不主张一上来加自动化。实际链路是客户提交→区域核对→补件→服务确认，先观察每个交接点，看重复核对到底卡在哪一段 。试点选点我倾向挑一个跨区域交接最频繁的批次，但具体是哪个区域、多少单量，尚未核实，需要林亦舟和唐映秋给出交接点样本后再定。 验收上我想确认两件事：一是材料完整性提示能否减少重复核对，二是服务单能否追溯。这两项的口径还需要和傅景对齐审核边界。你能先明确试点批次的选取标准和验收口径由谁确认吗？

### 林亦舟 · 一线服务专员

**问（痛点）**：你日常有哪些痛点，最费时间的环节是什么？

**答**：兜底这块我先把边界说清楚：按现有协作规则，无法确认入职服务单版本或关键字段时，必须进入人工处理队列，必要时暂停试点，不能默认通过 。这条是我审核职责的底线，不能靠一线自行判断放行。 但“哪些情况算关键字段无法确认”“转人工由谁触发、多久响应、暂停试点由谁批”，目前尚未核实，我不做假设。我的建议是：把触发条件、转人工入口、响应时限和暂停审批人列成责任清单，作为质量验收项之一，待验证后再定稿。 另外想追问：转人工后的处理记录是否要留存可审计？这直接影响我能否签字验收。

**问（审计）**：审计需要什么凭证，怎么追溯修改？

**答**：审计凭证这块，我的底线是能还原“谁查过、用的哪个版本、提了什么建议、谁确认的”，不能只留一个最终摘要 。修改追溯同理，原始版本、修订原因、确认人都要留存，练习结束后按项目约定删除虚构个人字段 。 但这里有个前提我还没核实：这些记录由哪个系统承载、保留多久、谁能查，目前没有依据，我不做承诺。如果试点阶段靠人工台账补，那质量验收时我会要求先明确台账的责任人和抽查方式。 想先跟你确认：你说的“追溯修改”，是只追入职服务单本身的状态变更，还是也要覆盖材料附件的替换？范围不同，我这边验收的检查项和权限约束会不一样。

### 叶书 · 客户协同代表

**问（协作）**：跨部门交接有哪些冲突？

**答**：从客户协同这边看，最直接的冲突是模板口径：客户要求统一模板，区域服务团队坚持保留本地材料差异 。这对我影响很实际——客户看到的是同一套入职体验，但区域交上来的材料形态不一致，我对外解释时容易说不清，也难判断哪些差异是合规必需、哪些只是习惯。 另一个是交接时的数据口径。同一入职服务单的数量、状态和截止时间，要在交接双方之间核对，以原始记录定义口径，而不是比较两张汇总表 。否则我拿到的进度和区域报的对不上，客户追问时我没法给准话。 我这边权限只到反馈和口径说明，改不了模板和流程。想先确认：这次试点是只统一对外模板，还是连本地差异的登记方式一起定？另外客户侧最在意的是时效还是材料完整性，需要你们明确，我才好把反馈归到可验收的口径上。

**问（指标）**：有多少单、花多久，有统计样本吗？

**答**：我这边能确认的是评估口径：协作评估既看入职服务单处理工时，也看返工次数和确认完整率，不能用单一效率指标解释效果 。至于具体有多少单、平均花多久，我手上没有可引用的统计样本，尚未核实，不能凭印象给数。 另外提醒一点：如果你们要拿数量、状态、截止时间做对比，得先明确以原始记录定义口径，而不是比较两张汇总表 ，否则跨区域两边对不上，客户侧反馈也会失真。 我想反问：你说的统计样本是试点范围内的单量，还是全量历史？验收时工时、返工、确认完整率这三项由谁出数、按什么周期取？这些没定，我这边没法向客户解释效果。

**问（边界）**：本次范围是什么，哪些事情不能自动做？

**答**：从客户协同口径看，范围我建议先限定在“材料完整性提示”这一层：跨区域入职材料收上来后，系统或协同流程只提示缺项、不一致，帮助减少重复核对，提高服务可追溯性。这个边界本轮是明确的：只做材料完整性提示，不自动办理入职，也不判断用工合法性；对外承诺仍由业务人员确认 。 所以自动触发入职、自动给员工或客户发结论性承诺、替业务判断能不能录用，这些都不能做。我这边最担心的是下游把“提示”理解成“结论”，引发客户预期偏差。试点范围具体覆盖哪些区域、哪些材料类型，目前尚未核实，需要和顾明岚、唐映秋对齐后再定。

**问（口径）**：不同团队对成功和完成的口径有哪些差异？

**答**：从客户协同这边看，口径差异主要落在“完成”到底以什么为准。我掌握的一条是：同一入职服务单的数量、状态和截止时间，要在交接双方之间核对，以原始记录定义口径，而不是比较两张汇总表 。这意味着客户侧看到的“已完成”和内部汇总表上的“已完成”可能不是一回事，投诉往往就出在这里。 另外，评估协作效果不能只看处理工时，还要看返工次数和确认完整率 ，否则客户体验会被单一效率指标掩盖。 我这边能说明下游口径和反馈，但具体各团队当前怎么定义“成功”，尚未核实。建议先拉一次口径对齐，把状态、截止时间、确认完整率三项逐条落到原始记录上；这只是待验证假设，需要业务负责人和流程协调员确认。

**问（投诉）**：客户投诉或反馈如何处理？

**答**：从我的口径，客户投诉或反馈不能靠推测客户意图来处理。客户投诉入职服务单结果错误时，我会先登记原始问题、相关版本和恢复需求，再拉对应团队确认 。反馈侧，我每周收集误报、漏报和未确认项，双方共同复盘；只改模板不核对效果，我不认为试点可以结束 。 但跨团队口径这块我还没拿到明确结论：谁受理、多久响应、哪些算误报、哪些算未确认，目前尚未核实。这些不确认，我无法向客户承诺处理时限，也无法判断复盘是否闭环。建议先和顾明岚、傅景把受理边界和复核责任对齐，再定试点内的反馈节奏；具体机制是待验证假设。

## 四、访谈结论摘要

- 一线与流程角色对"链路四节点"的描述一致：客户提交 → 区域核对 → 补件 → 服务确认。
- 分歧一：版本判定依据。规则判定（有效期 + 确认状态）与人工倒查原始版本并存。
- 分歧二：系统链路与现场做法并行——现场先用群消息处理，再回填表格，回填时间不等于发生时间。
- 分歧三：验收严格度。业务侧给抽查比例，审核侧追加"每条结果须可关联来源与复核记录"。
- 待补：一次具体事件的单号、日期、区域；真实单量、平均耗时、返工率、复核人力成本。
